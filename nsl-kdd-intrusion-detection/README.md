# NSL-KDD Intrusion Detection Research Prototype

Binary classification of recorded NSL-KDD connections: `0 = Normal`, `1 = Attack`. This is a dataset-based research prototype, not live traffic monitoring or a production intrusion prevention system.

## Setup

From this directory, create a virtual environment and install dependencies:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Place `KDDTrain+.txt` and `KDDTest+.txt` in `data/`. See `data/README.md` for sources. The dataset files are intentionally ignored by Git.

## Train model artifacts

```powershell
python main.py --train-artifacts
```

This trains Decision Tree, Random Forest, XGBoost, and XGBoost + Feature Engineering, saving locally ignored artifacts under `artifacts/`. The artifact training pipeline splits the combined data before fitting categorical encoders and MinMaxScaler, avoiding preprocessing leakage for its holdout evaluation. This corrected leakage-free evaluation is distinct from legacy recorded dashboard metrics and should not be described as exact reproduction of paper metrics. Artifacts use Python pickle/joblib serialization; only load artifacts generated by this trusted local training pipeline.

The existing full research experiment remains available with `python main.py`.

## Sample CSVs

`samples/` contains small samples extracted from the official `KDDTest+.txt` holdout file, rather than the training file. Note: the current artifact-training command combines both official files before making its own 80/20 split, so these sample rows are not guaranteed to be unseen by that trained model; use a separately held-out evaluation to estimate generalization. Each has 25 raw selected features and an `actual_label` column for evaluation only. `actual_label` is never a model input. Regenerate them after dataset setup with:

```powershell
python samples/make_samples.py
```

Use Raw format for these sample files. To create a valid preprocessed CSV from any compatible raw CSV, select the model and use the UI's **Download preprocessed copy** action. The output has that model's exact encoded/scaled feature columns (32 columns for XGBoost + Feature Engineering; 25 for the other models) and preserves an optional `actual_label`. Preprocessed mode validates numeric values and does not transform them again. These tiny examples are for demonstrating the workflow, not estimating generalization accuracy.

## Run backend

From repository root:

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

The API starts at `http://127.0.0.1:5000`. Check `GET /api/health` and `GET /api/models`. The API can start without artifacts for the research results page, but prediction endpoints return HTTP 503 until artifacts are generated. If needed, set `NSLKDD_ARTIFACT_DIR` to the artifacts directory. `CORS_ORIGINS` defaults to `*`; set it to comma-separated allowed origins in a deployed setup.

## Run Angular frontend

```powershell
cd frontend
npm ci
npm start
```

Open `http://localhost:4200`. The API URL defaults to `http://localhost:5000`. To override it before the app loads, set `globalThis.NSLKDD_API_URL` in a small deployment bootstrap script. GitHub Pages is static and cannot access local model artifacts; run/deploy Flask separately. No fictional public backend URL is configured.

## API examples

A single-record request must include all 25 raw selected features. Example shape (abbreviated here; abbreviated requests correctly fail validation):

```json
{
  "model": "random_forest",
  "input_format": "raw",
  "features": {
    "duration": 0,
    "protocol_type": "tcp",
    "service": "http",
    "flag": "SF"
  }
}
```

`POST /api/predict` returns the predicted class and probabilities when supported. A complete feature list is in `src/preprocessing.py`. Unknown categories are rejected. CSV uploads use `POST /api/predict/csv` as multipart form data: fields `model`, `input_format`, and file field `file`. `POST /api/preprocess/csv` accepts a raw CSV and returns a model-specific numeric CSV for download; upload that output with `input_format=preprocessed` to verify the second path. Optional `actual_label` values may be `Normal`/`Attack` or `0`/`1`; metrics are only returned when valid labels are supplied. Upload limit is 5 MB and 5,000 rows. The endpoint rejects malformed rows rather than silently dropping them.

Example PowerShell CSV request:

```powershell
curl.exe -X POST http://127.0.0.1:5000/api/predict/csv -F "model=random_forest" -F "input_format=raw" -F "file=@nsl-kdd-intrusion-detection/samples/sample_mixed.csv"
```

Single-record curl example requires a JSON file containing all selected features:

```powershell
curl.exe -X POST http://127.0.0.1:5000/api/predict -H "Content-Type: application/json" --data-binary "@record.json"
```

## Troubleshooting

- **Dataset missing:** put both official `.txt` files in `data/`.
- **Artifacts missing:** run `python main.py --train-artifacts` from this directory.
- **Unknown category:** the raw value was not present in training; correct the value or retrain with representative data.
- **Feature schema mismatch:** use the exact 25 raw feature names or model-specific preprocessed columns in metadata.
- **API unavailable/CORS:** start Flask, verify `/api/health`, and configure `CORS_ORIGINS` for the frontend origin.
- **Dependencies:** use a supported Python version and install the relevant `requirements.txt` file.
- **GitHub Pages:** static hosting does not run Python models. Flask must run separately.
